# 账号、注册、登录、找回密码与会话总规范

## 一、启用边界与默认方案

`M-ACCOUNT` 默认关闭。项目存在普通用户账号、注册、登录、找回密码或会话时才启用。

项目未指定时推荐：

- 邮箱 + 密码登录；
- 邮箱 + 邮箱验证码登录；
- 邮箱验证码 + 密码注册；
- 邮箱验证码找回并重置密码；
- Access Token + Refresh Token；
- 用户退出当前设备，后台可强制下线；
- 复用母版企业 SMTP。

项目明确使用手机号、用户名或其他方式时按需求替换，禁止为了“通用”一次实现所有登录方式。手机号短信方案必须由项目提供真实短信服务资料，母版不得虚构。

## 二、密码登录

```text
填写账号和密码
→ 点击登录
→ 弹出项目原生图形验证码
→ 验证成功并获得 LOGIN_PASSWORD 一次性票据
→ 自动提交账号和密码
→ 后端校验票据、频控、账号状态和密码
→ 创建会话与设备记录
→ 返回用户信息和 Token
→ 进入项目首页
```

每次点击登录都必须重新完成验证码。登录错误统一提示“账号、密码或安全验证不正确”，不暴露账号是否存在。

## 三、验证码登录

```text
填写邮箱/手机号
→ 点击发送验证码
→ 弹出图形验证码并获得 SEND_VERIFICATION_CODE 票据
→ 后端频控并发送业务验证码
→ 用户填写业务验证码
→ 点击登录
→ 再弹出图形验证码并获得 LOGIN_CODE 票据
→ 自动完成验证码登录
```

发送验证码和最终登录是两个动作，各自使用一次性票据，禁止跨动作复用。

## 四、注册

```text
填写邮箱/手机号等注册标识
→ 点击发送验证码
→ 图形验证码门禁
→ 发送业务验证码
→ 填写业务验证码、密码、协议等字段
→ 点击注册
→ 再弹出图形验证码
→ 后端校验注册票据、业务验证码、唯一约束和注册规则
→ 原子创建用户、登录标识和凭据
→ 按项目规则进入首页或登录页
```

注册模式支持开放、仅邀请码和关闭。注册最终提交必须单独通过验证码，不得只依赖发送业务验证码时的验证结果。

## 五、找回与重置密码

```text
输入账号标识
→ 点击获取重置验证
→ 图形验证码
→ 返回统一外部提示并按规则发送业务验证码
→ 用户输入业务验证码与新密码
→ 点击重置密码
→ 再弹出图形验证码
→ 后端校验一次性重置令牌与 PASSWORD_RESET_SUBMIT 票据
→ 更新密码并按配置撤销旧会话
→ 返回登录页或按项目规则自动登录
```

无论账号是否存在，外部均显示“若账号有效，将发送验证信息”。发送重置验证和最终重置分别验证。

## 六、密码、会话和账号生命周期

- 密码不得明文或可逆保存；优先 Argon2id，技术栈限制时使用合理成本的 bcrypt；
- Access Token 短时有效；Refresh Token 轮换、可撤销、只存摘要；
- Android Token 使用安全存储；管理后台 Cookie 使用 Secure、HttpOnly、SameSite 和 CSRF 防护；
- 支持退出当前设备、按需退出全部设备、管理员强制下线和设备会话列表；
- 至少定义待验证、正常、临时限制、冻结、注销处理中和已注销状态；
- 注销、冻结、解封、密码修改和强制下线全部审计。

## 七、管理后台

后台提供用户列表、详情、账号状态、登录标识、设备会话、登录日志、强制下线、冻结/解封、注销处理、关联实名/订单/内容/文件和操作审计。管理员不开放公共注册，每次登录提交必须使用自研图形验证码。

## 八、轻量边界

首版不默认建设社交账号登录、多因素认证平台、风险评分引擎、复杂设备指纹或统一身份中台；只有项目明确需要时才增加。
