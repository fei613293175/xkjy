# 页面返回状态保持与禁止无故重载规范

> 作用域：全局强制。适用于 Android App、管理后台、H5、独立弹窗、列表/详情链路以及外部 App 或系统页面返回。

## 1. 用户体验目标

用户在一个页面中滚动、筛选、搜索、切换 Tab、翻页、展开内容或填写表单后进入下一页面，再返回时，应立即回到离开前的上下文，不需要重新寻找位置，也不应看到白屏或整页重新加载。

## 2. 必须保留的页面状态

按页面实际存在的能力保存：

- 列表稳定条目 ID、滚动锚点和像素偏移；
- 普通滚动容器的滚动位置；
- 当前 Tab、子分类、折叠/展开状态；
- 搜索词、筛选项、排序项、分页页码或游标；
- 已选条目、多选状态和批量操作上下文；
- 未提交的表单草稿、输入焦点和字段校验结果；
- 当前已加载数据、空状态、局部错误和分页加载状态；
- 外部支付、相机、相册、文件选择器和系统权限跳转前的业务上下文。

## 3. 禁止行为

- 返回时重新导航到一个新的来源页面实例；
- 返回即滚动到顶部；
- 返回即清空列表、筛选、分页、Tab 或草稿；
- 在 `onResume`、页面重组或路由返回时无条件重新请求全部数据；
- 有可用旧内容时先清空页面并显示全屏白屏或骨架屏；
- 为刷新一条数据而重新加载整个页面；
- 浏览器返回时执行整页刷新。

## 4. Android 实现基线

- 使用导航返回栈 `popBackStack` 返回，不重新 `navigate` 到来源路由；
- 底部主导航的每个一级 Tab 保持独立返回栈、滚动和子页面状态，切换 Tab 不得重建首页；
- 页面业务状态由页面/导航图作用域的 ViewModel 或等价状态容器持有；
- 使用 `SavedStateHandle` 保存可安全恢复的路由参数、筛选、草稿和位置；
- Compose 的短暂 UI 状态使用 `rememberSaveable`，不得把它当作业务唯一事实源；
- `LazyColumn`、`LazyGrid` 等使用稳定 item key，并优先保存“稳定条目 ID + 偏移”，避免数据插入后索引错位；
- 首次无缓存进入时加载；返回、重新组合或普通前后台切换不得自动全量加载；
- 详情页修改数据后，优先局部更新来源列表对应条目；条目删除时保持邻近位置；
- 需要刷新时采用保留现有内容的后台刷新，不先清空界面。

## 5. 管理后台与 H5 实现基线

- 使用 SPA 路由和浏览器历史栈，禁止返回时整页重载；
- 列表筛选、排序、页码等可写入路由查询参数或页面级状态仓库；
- 滚动位置和临时页面状态按路由实例保存，必要时使用 `history.state` 或 `sessionStorage`；
- 从详情返回列表时恢复原筛选、页码、滚动锚点和已选列；
- 表格刷新只更新数据区域，不重置整个页面布局和导航状态。

## 6. 刷新策略

允许刷新不等于允许清空状态。默认策略：

```text
显示当前状态与已有内容
→ 后台检查数据是否需要更新
→ 成功后局部合并
→ 失败时保留现有内容并给出非阻断提示
```

以下情况可以刷新或重置，但必须在页面规格中登记：

- 用户主动下拉刷新或点击刷新；
- 登录状态、角色或权限已失效；
- 当前数据已删除、撤回或不再允许展示；
- 安全敏感页面超时；
- 明确业务操作要求返回后切换到新状态；
- App 进程被系统销毁且敏感状态不得落盘。

## 7. 进程和生命周期恢复

- 同一 App 任务和返回栈内必须精确恢复；
- 配置变化、切后台再回来不得丢失页面状态；
- 进程重建后至少恢复可安全持久化的路由、筛选、草稿和列表位置；
- 密码、验证码、身份证和其他敏感字段按安全规则决定是否恢复，不得为状态保持降低安全性。

## 8. 页面文档要求

每个 Page ID 必须填写：

- 返回时需要保留的字段；
- 状态所有者；
- 滚动恢复键；
- 刷新触发条件；
- 数据局部合并策略；
- 允许重置的明确例外；
- 真机或浏览器验证步骤。

## 9. 验收标准

- 深度滚动进入详情后返回，仍停留在同一条目和相同视觉位置；
- 筛选、搜索、排序、Tab、分页和展开状态保持；
- 返回过程中不出现全屏白屏或无意义全屏加载；
- 返回不会重复触发相同网络请求；
- 子页面修改只更新受影响内容；
- 外部支付、相机和文件选择器返回后原页面上下文保持；
- 管理后台浏览器返回不丢失表格状态。
