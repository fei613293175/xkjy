# 自研图形安全验证码与接口防刷总规范

## 1. 适用范围

以下动作必须在用户点击提交后弹出项目自有的图形验证码，并在验证通过后自动继续原请求：

- 管理后台登录；
- App 密码登录和验证码登录；
- App 注册最终提交；
- 找回密码请求和重置密码最终提交；
- 发送邮箱或短信验证码；
- 项目明确标记的其他高风险匿名写接口。

这些强制动作固定为 `ALWAYS`，不得由普通后台开关关闭。验证码是后端门禁，不只是客户端弹窗；直接绕过弹窗调用业务 API 时，后端必须拒绝。

## 2. 用户交互

```text
用户填写业务表单
→ 点击登录/注册/找回/发送验证码等按钮
→ 原生 App 或管理后台弹出图形验证码
→ 用户输入验证码
→ 验证成功后弹窗关闭
→ 客户端自动继续刚才的业务请求
→ 表单内容、页面位置和操作上下文全部保留
```

每一个受保护的业务提交都需要一张新的、用途绑定的验证码票据。例如“发送注册邮箱验证码”和“最终提交注册”是两个独立动作，分别验证，禁止用一次通过结果跨动作复用。

## 3. 自研边界

- 验证码由项目后端自行生成，不接任何第三方服务；
- 使用密码学安全随机数生成字符、挑战 ID 和随机扰动；
- 图片在内存中生成并直接返回 Base64/Data URI，不上传 R2，不保存到用户相册；
- 图片响应设置 `Cache-Control: no-store`；
- 正确答案不返回客户端、不写日志、不进入埋点；
- 服务端不明文保存答案，使用服务器私有密钥和 challenge nonce 计算 HMAC 校验值；
- 比较 HMAC 时采用常量时间比较；
- 优先复用项目已有共享缓存；没有缓存时可使用支持原子更新的短期数据库记录和定时清理，禁止只为验证码强制引入 Redis。

## 4. 两阶段门禁

1. 服务端创建 `challenge`，返回不可预测的 `challenge_id`、图片、有效期和服务端签发的匿名会话令牌；
2. 用户输入后调用验证接口；
3. 验证成功后签发短时一次性 `captcha_ticket`；
4. 原业务接口携带 `X-Captcha-Ticket`；
5. 后端核对用途、服务端匿名会话、目标摘要、有效期、消费状态和频控；
6. 业务请求进入有效处理时原子消费票据，禁止并发重放。

验证码票据不能替代密码、邮箱验证码、短信验证码、登录 Token 或权限校验。

## 5. 推荐默认值

- 5 位大写字母与数字，排除 `0/O/1/I/L`；
- 图片 160×56；
- 字体轻度旋转、4 条干扰线和适量噪点，兼顾可读性；
- challenge 有效期 120 秒；
- 每个 challenge 最多 3 次输入；
- ticket 有效期 180 秒且只能使用一次；
- challenge ID 至少 128 位随机熵；
- 刷新最短间隔 2 秒，刷新后旧 challenge 立即失效；
- 大小写不敏感。

参数允许后台调整，但强制保护动作不得关闭。修改参数必须经过权限、校验、原因和审计。

## 6. 防刷组合

图形验证码必须与以下频控组合：

- IP；
- 服务端匿名会话；
- App 安装/设备风险标识；
- 账号标识；
- 邮箱或手机号目标；
- 接口用途；
- 时间窗口。

账号是否存在、是否发送成功等外部响应保持一致，避免账号枚举。连续失败采用短时递增等待，禁止攻击者通过恶意失败永久锁死他人账号。

## 7. 页面、后台与可观测性

图形验证码弹窗属于共享独立 Page ID，必须具备默认、加载、输入错误、过期、刷新、频控和通过状态。后台提供参数设置、生成量、通过率、失败、过期、票据消费、重放拦截和高频来源统计，不展示答案、图片内容或可逆数据。
