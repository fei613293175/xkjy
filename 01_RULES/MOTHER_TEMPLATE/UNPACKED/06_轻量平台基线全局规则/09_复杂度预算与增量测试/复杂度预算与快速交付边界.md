# 复杂度预算与快速交付边界

## 开发顺序

```text
核心用户流程
→ 必要后端和数据库
→ 必要企业级后台闭环
→ 必要第三方接口
→ 真机可用
→ 最小日志、健康和配置
→ 非必要平台能力
```

## 强制限制

- 未被项目需求或依赖触发的模块禁止开发；
- 每个小版本默认最多新增一个平台型模块；
- 允许预留接口、字段和模块边界，禁止提前完整实现未来系统；
- 后台按大型公司质量标准建设，但功能范围只覆盖真实业务；
- 不强制微服务、Kubernetes、多套长期环境、完整 BI、灰度、工作流或全链路平台。

## 测试策略

小版本完整测试新增、修改和受影响页面，未修改主流程做冒烟；阶段和最终版本进行全量页面、关键流程和视觉回归。既不能每次微调都重复全量耗时，也不能遗漏影响范围。
