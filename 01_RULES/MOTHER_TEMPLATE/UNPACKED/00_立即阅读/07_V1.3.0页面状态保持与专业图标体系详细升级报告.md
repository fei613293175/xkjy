# V1.3.0 页面状态保持与专业图标体系详细升级报告

## 一、升级目标

本次只增加两项全局高收益质量基线，不新增业务模块，不建设重型平台：

1. 解决页面返回回顶、白屏和无故重新加载；
2. 解决文字、Emoji 和风格混乱图标造成的低质量 UI。

## 二、页面状态保持

新增 G-046、`LB-PAGE-STATE` 和四份状态合同/测试文件。所有 App、后台和 H5 页面必须保存实际存在的滚动位置、Tab、筛选、搜索、排序、分页、展开、选择、草稿和已加载内容。

默认禁止返回和 `onResume` 全量重载。确需刷新时保留旧内容后台刷新并局部合并。登录/权限失效、数据删除、安全超时等例外需要逐页登记。

## 三、专业图标体系

新增 G-047、`LB-ICON`、Icon Registry 和图标验收规则：

- 通用功能默认使用 Remix Icon SVG；
- 支付宝、微信等使用官方品牌资产；
- 项目专属核心功能使用定制 SVG；
- 无官方资产时使用中性类别 SVG + 正常文字标签；
- 禁止“支”“微”“A”“1”“￥”、Emoji、Unicode 和 Icon Font 充当图标；
- 最终项目包必须带上实际使用的 SVG，避免 Codex 临时替换。

## 四、覆盖范围

已同步修改：

- G 规则和规则目录；
- 轻量平台基线和解析模板；
- Page Spec、Page Index、Design Token；
- 全量页面和视觉验收规则；
- 企业级后台规范；
- Android 原生收银台；
- 真机测试、交付清单和视觉报告；
- ChatGPT 与 Codex 入口指令；
- 模板状态、索引、总纲和迁移映射。

## 五、复杂度控制

页面状态保持复用统一状态容器和导航规则；图标体系只登记实际使用资产。两项不生成额外业务页面、数据表、第三方服务或大型平台，因此不会明显扩大项目功能范围。

## 六、最终效果

以后生成的新项目必须同时满足：

- 用户返回页面仍在原来的位置和上下文；
- 有数据时不因返回先白屏再加载；
- 支付方式和所有功能入口使用真实专业图标；
- 效果图、SVG、Icon Registry 和代码完全对应；
- 真机验收包含页面状态恢复和图标专项测试。
