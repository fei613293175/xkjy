七、判断是否启用账号模块：只要项目需要普通用户注册、登录、找回密码或用户会话，就启用 M-ACCOUNT。未明确登录方式时，推荐邮箱 + 密码和邮箱 + 邮箱验证码，并自动启用邮箱模块。

八、自研图形安全验证码不接第三方：管理后台登录始终使用；App 登录、注册、找回密码和发送验证码在用户点击提交后先弹出原生验证码，通过后自动继续原业务。后端必须校验一次性 captcha_ticket，禁止只做前端弹窗。

九、整个项目所有 Android、后台、H5、弹窗和关键状态必须有 Page ID、完整页面规格、实际 UI 数值、Design Token、独立 HTML/CSS/SVG 和 PNG 效果图。当前母版本身不生成效果图。

十、每个 Page ID 必须制定页面返回状态合同：进入下一页面后返回时保留滚动位置、Tab、搜索、筛选、排序、分页、草稿和已加载内容；禁止回顶、白屏和无故全量重载。允许重置的安全或业务例外必须逐页写明。

十一、为整个项目建立 `ICON_REGISTRY.yaml`。通用功能默认采用 Remix Icon SVG，品牌使用官方资产，项目专属功能使用自定义 SVG；禁止用汉字、字母、数字、Emoji、符号或 Icon Font 充当图标。项目包必须附带所有实际使用的 SVG。

十二、企业级后台是质量标准，不是无限功能范围。必须好用、可观测、可控、可审核和可追溯，但不得擅自建设未触发的 BI、工作流、灰度或事故平台。

十三、输出项目包前验证：G 规则完整、轻量基线已解析、账号与验证码流程一致、页面返回状态合同完整、Icon Registry 与 SVG 完整、依赖正确、关闭模块无残留、全部页面和后台规格完整、Codex 可以直接执行。支付启用时额外验证 XApay MD5 签名、回调/查单幂等、扫码随机收款码、截图审核、权益和返佣结算、订单类型隐藏双重校验。提现启用时额外验证实名锁名、金额精度、冻结账本、每日次数、证书预检、签名验签、查单对账和真实资金授权边界。
