# 模块选用、依赖与裁剪规则

## 一、模块分类

### 五项固定第三方能力

- `identity_verification`：当前阿里云市场 sdfaceid 实名套餐；
- `payment`：富运收款与 Android 原生收银台；
- `storage`：Cloudflare R2；
- `email`：SMTP 企业邮箱；
- `withdrawal`：支付宝 RSA2 证书出款及提现业务闭环。

它们包含接口合同、私有配置和实现规则，默认关闭，按需求启用。

### 可选平台复用模块

- `account`：注册、登录、找回密码、会话和账号后台。

### 全局轻量基线

统一 API、最小更新、迁移备份、结构化日志、最小配置、幂等重试、依赖锁定、自研图形验证码和复杂度预算属于 G 规则，不是模块开关。

## 二、依赖解析

| 选择 | 自动解析结果 |
|---|---|
| 启用实名认证且后台可免费/收费切换 | 自动启用对象存储和支付 |
| 实名认证固定永久免费 | 自动启用对象存储；支付可不因实名启用 |
| 启用支付 | 固定包含 Android 原生收银台和第三方收款适配 |
| 启用提现 | 自动启用账号和实名认证；要求项目实现可用/冻结余额与幂等账本；复制支付宝证书私有凭据 |
| 启用账号模块 | 自动应用自研图形验证码基线 |
| 账号使用邮箱验证码 | 自动启用邮箱模块 |
| 账号使用短信验证码 | 必须由项目提供短信供应商、签名和模板，未提供时不得伪造真实发送 |

自动依赖必须写入 `RESOLVED_RULESET.yaml`，并标注 `activation_reason: dependency`。提现依赖的事务钱包账本若项目不存在，必须作为提现模块的一部分实现，不得用简单余额字段绕过。

## 三、私有配置裁剪

- 实名只复制当前 AppCode，不复制已废弃商家信息；
- 提现启用时复制 `withdrawal_payout` 配置和四个支付宝 Secret 文件；
- 提现关闭时任何证书、私钥和出款 App ID 都不得进入项目包；
- 配置和 Secret 仅部署到后端服务器，不进入客户端、静态前端或公开仓库。

## 四、关闭模块彻底裁剪

关闭模块不得进入功能矩阵、Page ID、效果图、API、数据表、迁移、后台菜单、配置、运行环境、版本范围、测试清单和 Codex 门禁。

## 五、防过重规则

- 轻量基线只实现最小闭环，不自动建设大型平台；
- 未触发模块禁止开发；
- 每个小版本默认最多新增一个平台型模块；
- 可预留接口、字段和模块边界，但不得提前完整实现“以后可能需要”的系统；
- 提现属于资金敏感完整闭环，不能为了“轻量”删掉冻结、幂等、查单、对账和审计。
