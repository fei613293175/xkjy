# 母版整合规则 T-001~T-014

这些规则只约束 ChatGPT 使用母版生成项目专属开发包。

### T-001 私有母版定位
本包是私有开发母版，不是具体项目和公开资料；必须同时保留五项固定第三方能力、轻量平台基线、可选平台复用模块和整个项目全局规则。

### T-002 四层规则分离
生成项目包时必须明确区分 T、G、M、P 四层：T 约束母版整合，G 对整个项目生效，M 仅在对应模块启用时生效，P 是当前项目专属规则。不得把条件模块写成所有项目强制业务，也不得把 G 规则当成可关闭模块。

### T-003 完整读取后整合
必须先读取规则作用域、G 规则、轻量平台基线、模块目录、私有配置、页面规范、企业级后台规范、服务器、Codex、真机和交付规范，再制定项目文档。

### T-004 已有信息不得重复索取
母版中已有的实名认证、支付、对象存储、邮箱、提现证书出款配置，以及主域名、服务器、真机和交付信息不得再次询问；只有真实验证出现明确失效、权限未开通、证书到期或供应商错误时才报告证据。

### T-005 G 规则完整继承
每个项目的 `RESOLVED_RULESET.yaml` 必须包含 G-001~G-047，任何缺失均视为项目包未完成。

### T-006 仅抽取已启用的五项固定第三方能力
实名认证、支付、对象存储、邮箱和提现默认关闭。仅把 `resolved_enabled: true` 的模块功能、规则、凭据、页面、API、数据表、后台和测试复制到项目包。提现关闭时不得复制支付宝证书和私钥。

### T-007 仅抽取已启用的平台复用模块
账号与会话等平台复用模块默认关闭，仅在当前项目存在对应业务时启用。未启用模块不得生成页面、数据表、后台菜单、测试或版本任务。

### T-008 解析全部依赖
实名认证默认依赖对象存储，保持后台免费/收费时依赖支付；支付固定包含 Android 原生收银台；提现依赖账号、实名认证和事务型钱包账本；账号模块必须使用自研图形验证码，使用邮箱验证码时自动依赖邮箱模块。所有自动启用项必须写入 `RESOLVED_RULESET.yaml`。

### T-009 生成已解析规则集
项目包必须包含 `RESOLVED_RULESET.yaml`、模块选择结果、轻量平台基线状态、依赖解析、规则覆盖登记和项目包内容矩阵，供 Codex 直接执行。

### T-010 当前项目需求精确整合
当前项目已确认的业务需求必须转化为 P 项目专属规则、功能矩阵、页面、API、数据库、后台、测试和版本计划，不得只复制母版通用文字。

### T-011 私有配置按需复制
只复制启用的五项固定第三方能力所需私有配置到项目私有目录；不得为关闭模块附带无关密钥。提现证书/私钥只进入启用提现的私有项目包和服务器 Secret 目录。所有密钥仍只供后端和服务器使用。

### T-012 项目效果图生成时点
母版本身不生成项目效果图。新项目业务、页面清单和 Design Token 确认后，才为整个项目所有 Page ID 生成独立 HTML/CSS/SVG 源文件和 PNG 效果图。

### T-013 轻量平台基线完整但不过度
标准 API、最小更新、迁移备份、结构化日志、最小配置、关键幂等、依赖锁定、自研验证码、页面状态保持、专业 SVG 图标体系和复杂度预算属于轻量基线。必须覆盖实际场景，但不得擅自扩展为重型平台；高级能力默认关闭。

### T-014 打包前适用性校验
输出项目 ZIP 前必须验证：G 规则无缺失、轻量基线已解析、模块依赖正确、关闭模块无残留、启用模块资料完整、账号流程与验证码门禁一致、每页状态恢复合同完整、Icon Registry 与实际 SVG 完整、全项目页面和后台规格完整、Codex 可立即执行。
