# 通用项目开发私有母版总纲 V1.4.2

## 第一章：总体目标

本母版用于统一 Android 原生 App、项目后端、数据库、企业级管理后台、必要 H5、第三方接口、部署、真机测试和版本交付。它保存五项可按需启用的固定能力：当前实名认证、富运/XApay在线支付与人工扫码审核支付、Cloudflare R2、SMTP 邮箱、提现与支付宝证书出款；并保存全项目规则、轻量平台基线和账号会话模块。

母版是高敏感私有资产，不是可公开发布的 SDK 或具体项目文档。`RESOLVED_RULESET.yaml` 是每个新项目的唯一适用性事实源，模块选择不得关闭 G 规则。

## 第二章：四层规则模型

- **T**：ChatGPT 如何读取和整合本母版；
- **G**：所有项目、所有业务和全部技术组成无条件生效；
- **M**：固定能力或平台模块启用时生效；
- **P**：当前项目专属业务、视觉和运营规则。

## 第三章：轻量平台基线

所有项目默认采用 `LIGHTWEIGHT_COMPLETE`：统一 API/错误码、Android 签名更新、迁移备份、日志健康、最小配置、幂等补偿、依赖锁定、自研图形验证码、页面状态保持、专业 SVG 图标和增量验收。未被需求触发时，不建设 BI、灰度、工作流、完整离线或高级风控平台。

## 第四章：五项固定第三方能力

### 4.1 基础实名认证

固定使用当前 `sdfaceid` 人脸身份证比对契约。包含服务端 AppCode 调用、动作采集、照片/视频私有临时处理、对象存储、人证比对、`resultCode` 分层判定、后台记录与人工处理。不是金融级活体认证。

### 4.2 收款支付

包含项目自有 Android 原生收银台、自有后端订单、富运在线支付、XApay支付宝/微信在线支付、支付宝/微信/QQ扫码人工审核、按订单类型隐藏方式、回调、验签、金额校验、幂等、查单、补单、统一权益/返佣结算和后台管理。收款支付不能替代提现出款。

### 4.3 对象存储

使用 Cloudflare R2 的项目隔离路径、上传/访问/删除/业务绑定、文件记录、日志与清理。凭据只在服务端。

### 4.4 邮箱

使用企业 SMTP 实现验证码、模板、频控、队列、重试、日志、测试发送和统计。

### 4.5 提现与支付宝证书出款

提现要求账号、通过的实名认证和事务型钱包账本。包含实名锁定姓名、固定档位、两位小数金额、冻结账本、每日次数、自动阈值出款、人工审核后一键接口出款、RSA2 证书模式、签名验签、查单对账、失败退回和审计。

四份支付宝材料只在提现启用时复制到服务器 Secret 目录。材料可复用不等于第三方权限或风控永久可用；上线前重新预检，真实资金验证必须得到当前项目的明确授权。

## 第五章：账号、验证码与页面体验

项目需要账号时启用 `M-ACCOUNT`，覆盖注册、密码/验证码登录、找回、会话、设备管理和后台。提现会自动启用账号与实名认证。管理后台登录，以及项目中存在的登录、注册、找回、重置和发送验证码动作，均使用后端自研的一次性图形验证码票据与频控。

所有页面从子页面、外部支付、相机或系统页面返回时，必须恢复滚动、Tab、筛选、分页、选择、草稿和已加载内容。全项目使用受登记的专业 SVG 图标，禁止文字、Emoji 或 Icon Font 代替图标。

## 第六章：新项目生成流程

```text
上传母版 + 新项目需求
→ 完整继承 G-001~G-047 与轻量基线
→ 选择五项固定能力与账号等平台模块
→ 自动解析实名/存储/支付/提现/验证码依赖
→ 生成 P 规则、功能矩阵、规则集与私有配置裁剪结果
→ 为全部 Page ID 生成状态合同、效果图和 SVG 图标
→ 打包私有项目开发包
→ Codex 在 obx-test 开发、真机测试并交付
```
