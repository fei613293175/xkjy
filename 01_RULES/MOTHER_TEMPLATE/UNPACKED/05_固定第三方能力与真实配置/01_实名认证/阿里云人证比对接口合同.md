# 阿里云市场人脸身份证比对接口合同

> V1.4.1 权威契约。旧 `kzfacev1.market.alicloudapi.com` 地址属于另一商品/商家，已确认不能用于本母版，禁止回退或混用。

## 固定请求契约

```text
Host: https://sdfaceid.market.alicloudapi.com
Path: /face_id_card/check
Method: POST
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
Authorization: APPCODE <AppCode>
```

完整 URL 必须由 HTTPS Host 与 Path 结构化拼接，禁止从客户端传入、禁止关闭 TLS 证书或主机名校验。AppCode 以 `PRIVATE_INTEGRATIONS.yaml` 为唯一事实源，仅部署到后端服务器。

## Body 字段

| 字段 | 必填 | 说明 |
|---|---:|---|
| `idcard` | 是 | 中国大陆居民身份证号 |
| `name` | 是 | 与身份证一致的姓名 |
| `image` | 二选一 | 人脸图片 Base64；使用标准表单编码，不能破坏 `+`、`/`、`=` |
| `url` | 二选一 | 服务端可访问的 HTTPS 图片 URL；与 `image` 只传一个 |

默认使用 `image`。后端读取对象存储中的加密照片、解密并压缩后转换为 Base64；不得把私有对象 URL 暴露给第三方之外的客户端。

## 响应判定

平台必须依次判断：HTTP 状态、外层调用状态、业务数据存在性、`data.resultCode`。任何一层异常都不得写成认证成功。

| `resultCode` | 业务含义 | 默认平台状态 |
|---:|---|---|
| `1001` | 姓名身份证匹配，人脸为同一人 | `VERIFIED` |
| `1002` | 姓名身份证匹配，人脸不能确定 | `RECAPTURE_REQUIRED` 或后台配置的人工复核 |
| `1003` | 姓名身份证匹配，人脸为不同人 | `FAILED` |
| `1004` | 无法识别、身份资料不匹配等 | `FAILED` |

成功时保存供应商 `orderNo`、`score`、`resultCode`、HTTP 状态、请求耗时和脱敏请求 ID。供应商响应结构发生变化时进入 `PROVIDER_ERROR`，禁止默认通过。

## 联调分层

1. 契约探测：以不含真实个人资料的无效参数确认 DNS、TLS、Host、Path 和返回结构。
2. 鉴权探测：在服务器使用私有 AppCode，确认不是 `Unauthorized`、`Invalid AppCode` 或套餐不匹配。
3. 业务联调：仅经所有者授权，使用合法测试人的姓名、身份证和现场照片验证 `1001~1004` 映射。

前两层通过不等于真实人证一定通过；第三层失败时必须区分资料/人脸不匹配、供应商额度、鉴权、网络和解析错误。

## 服务端实现要求

- 仅后端调用，Android、H5、后台前端均不得获得 AppCode；
- 连接和总请求超时必须配置，网络错误只允许有限重试；业务失败不得自动重试；
- 姓名、身份证、图片、AppCode、原始响应和堆栈不得进入普通日志；
- 以平台认证会话 ID 做幂等，重复回调/重试不能创建多个最终结果；
- 图片必须使用表单编码器，不得手工字符串拼接；
- 供应商不可用时返回中文业务错误并保留可重试状态，不得伪造认证结果；
- 已认证用户再次进入入口时直接读取服务器认证状态并展示成功页；
- 摄像头仅在采集页和采集时段启用，离页、后台、完成、失败或取消立即解绑并停止。
