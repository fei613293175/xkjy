# 富运支付离线开发合同

- 基础地址：`https://fuylink.cy253.top/`
- 请求编码：UTF-8
- 请求格式：`application/x-www-form-urlencoded`
- 返回格式：JSON
- 签名：MD5，小写
- 本合同按 2026-08-12 可访问的在线开发文档整理。

## 一、页面跳转支付（兼容能力）

```text
POST/GET https://fuylink.cy253.top/submit.php
```

推荐 POST。字段：

| 参数 | 必填 | 说明 |
|---|---:|---|
| `pid` | 是 | 商户 ID |
| `type` | 否 | 支付方式；不传可能进入第三方收银台，本项目默认不采用该模式 |
| `out_trade_no` | 是 | 商户唯一订单号 |
| `notify_url` | 是 | 服务端异步通知地址 |
| `return_url` | 是 | 页面返回地址 |
| `name` | 是 | 商品名称，过长会被截断 |
| `money` | 是 | 元，最多两位小数 |
| `param` | 否 | 原样返回的业务参数 |
| `sign` | 是 | 签名 |
| `sign_type` | 是 | `MD5` |

本母版的 Android 原生收银台优先使用后端 API 支付，不依赖第三方收银台。

## 二、API 发起支付（默认方案）

```text
POST https://fuylink.cy253.top/mapi.php
```

| 参数 | 必填 | 说明 |
|---|---:|---|
| `pid` | 是 | 商户 ID |
| `type` | 是 | `alipay`、`wxpay` 或 `usdt` |
| `out_trade_no` | 是 | 商户唯一订单号 |
| `notify_url` | 是 | 异步通知地址 |
| `return_url` | 否 | 页面返回地址 |
| `name` | 是 | 商品名称 |
| `money` | 是 | 订单金额 |
| `clientip` | 是 | 用户发起支付的 IP |
| `device` | 否 | 设备类型，App 推荐按接口能力传 `mobile` 或 `jump` |
| `param` | 否 | 不透明业务关联值 |
| `sign` | 是 | MD5 签名 |
| `sign_type` | 是 | `MD5` |

成功返回 `code=1`，并只会出现以下三个字段之一：

- `payurl`：第三方支付跳转 URL；
- `qrcode`：二维码原始内容；
- `urlscheme`：可唤起小程序或外部支付应用的 Scheme。

同时可能返回 `trade_no` 和 `msg`。

## 三、支付通知

第三方向 `notify_url` 和 `return_url` 使用 GET 发送：

- `pid`
- `trade_no`
- `out_trade_no`
- `type`
- `name`
- `money`
- `trade_status`
- `param`
- `sign`
- `sign_type`

仅 `trade_status=TRADE_SUCCESS` 表示支付成功。

异步通知处理成功后，后端返回纯文本：

```text
success
```

## 四、签名算法

1. 移除 `sign`、`sign_type` 和空值字段。
2. 按参数名 ASCII 升序排序。
3. 拼成 `a=b&c=d&e=f`，参数值不先做 URL 编码。
4. 在字符串末尾直接拼接商户密钥。
5. 计算 MD5，输出小写十六进制。

伪代码：

```text
pairs = sort(non_empty(params - sign - sign_type))
plain = join("&", key + "=" + value for each pair)
sign = lower(md5(plain + merchant_key))
```

## 六、设备类型

| device | 说明 |
|---|---|
| `pc` | 电脑浏览器 |
| `mobile` | 手机浏览器 |
| `qq` | 手机 QQ 内浏览器 |
| `wechat` | 微信内浏览器 |
| `alipay` | 支付宝客户端 |
| `jump` | 仅返回支付跳转 URL |

## 七、商户信息查询

```text
GET /api.php?act=query&pid={pid}&key={merchant_key}
```

返回商户状态、余额、结算方式、结算账号、订单总数和今日/昨日订单等。只允许后端或后台运维调用，URL 日志必须对 `key` 脱敏。

## 八、结算记录查询

```text
GET /api.php?act=settle&pid={pid}&key={merchant_key}
```

成功时返回 `code`、`msg` 和 `data` 记录数组。

## 九、单个订单查询

```text
GET /api.php?act=order&pid={pid}&key={merchant_key}&out_trade_no={out_trade_no}
```

也可传 `trade_no`，两者都传时以 `trade_no` 为准。主要返回：第三方订单号、商户订单号、支付方式、金额、创建/完成时间、支付状态和买家信息。

`status=1` 表示成功，`status=0` 表示未支付。

## 十、批量订单查询

```text
GET /api.php?act=orders&pid={pid}&key={merchant_key}&limit={limit}&page={page}
```

`limit` 最大 50，返回分页订单数组。

## 十一、退款

```text
POST https://fuylink.cy253.top/api.php?act=refund
```

需要商户后台先开启退款 API。

参数：`pid`、`key`、`money`，并在 `trade_no` 与 `out_trade_no` 中至少传一个；同时传时优先 `trade_no`。

## 十二、本项目标准实现

- App 原生收银台；
- 后端 `/mapi.php` 发起；
- 回调验签和金额核对；
- 本地订单唯一约束；
- 权益幂等；
- 回调失败记录和重试；
- 未确认订单主动查询；
- App 回前台轮询自有后端；
- 所有商户密钥只在服务器端。
