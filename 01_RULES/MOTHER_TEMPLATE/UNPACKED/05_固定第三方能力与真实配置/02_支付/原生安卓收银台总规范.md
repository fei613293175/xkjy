# Android 原生收银台总规范

> 作用域：仅当 `payment.resolved_enabled: true` 时进入项目。原生收银台与第三方支付属于同一个支付模块。

## 1. 核心边界

收银台是本项目 App 的原生页面，由 Kotlin + Compose 开发。第三方支付站点不承担本项目收银台 UI。

## 2. 页面信息

- 项目 Logo 或品牌区域；
- 订单名称和业务说明；
- 商品明细；
- 订单号；
- 原价、优惠、应付金额；
- 后台已启用的支付方式；
- 订单倒计时；
- 支付协议/提示；
- 支付按钮；
- 取消和返回规则；
- 处理中、成功、失败、取消、过期和查询中状态。

所有页面和状态建立独立 Page ID，视觉跟随当前项目，不允许所有项目使用同一套收银台外观。

## 3. 交互流程

1. App 只提交商品标识、数量和业务上下文给自有后端。
2. 后端按正式商品配置计算金额并创建订单。
3. App 获取订单详情和由服务端按订单类型过滤后的可用支付方式，打开原生收银台。
4. 用户选择方式并点击支付。
5. App 请求自有后端 `发起支付`；服务端再次按订单类型过滤所选方式。
6. 后端根据 profile 调用富运 `/mapi.php` 或 XApay `/xpay/epay/submit.php`；人工扫码方式创建扫码会话，不调用在线网关。
7. 根据返回值：
   - `payurl`：打开受控第三方支付页面；
   - `urlscheme`：校验 Scheme 后唤起外部 App；
   - `qrcode`：进入项目自有原生二维码支付状态页；
   - `manual_qr`：打开扫码收款弹窗，显示金额、随机收款码、保存图片和“必须截图上传付款记录”的提交入口。
8. App 回前台后只查询自有后端订单状态。
9. 在线支付权益由后端异步回调或主动查询确认后幂等发放。
10. 人工扫码审核通过后复用同一权益发放、返佣和支付事件流水；审核拒绝不得发放任何权益。

## 4. 禁止

- App 计算或决定最终金额；
- App 持有商户密钥；
- 用第三方默认收银台代替原生收银台；
- 仅凭 return_url 或客户端成功提示发放权益；
- 重复点击生成多笔不可控订单；
- 把第三方错误堆栈直接显示给用户。
- 只在支付方式列表中过滤而不在发起支付接口再次校验；
- 人工扫码未审核、截图缺失或订单金额不一致时发放权益。


## 5. 支付方式图标

- 支付宝、微信等支付方式必须使用官方品牌图标或支付服务商正式提供的品牌资产；
- 禁止使用“支”“微”“WX”等文字充当支付图标；
- 无官方资产时使用钱包、二维码等中性 SVG 图标，并在旁边显示完整支付方式名称；
- 图标写入全项目 `ICON_REGISTRY.yaml`，效果图、Android 代码和后台配置预览使用同一资产；
- 从第三方支付 App 返回原生收银台或订单状态页时，必须保留订单、支付方式、倒计时和页面上下文，不得白屏或重新创建无关订单。
