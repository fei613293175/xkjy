# 按订单类型隐藏支付方式规范

## 1. 目标

运营可为每个支付方式选择不允许出现的订单类型。例如会员和幸运卡订单可隐藏富运支付宝，但其他商品仍可使用。配置粒度是“支付方式 + 订单类型”，不是全局关闭支付方式。

## 2. 数据字段

`payment_method_configs.hidden_order_kinds JSON/JSONB NOT NULL DEFAULT []`

允许枚举：

| 值 | 含义 |
|---|---|
| `MEMBERSHIP` | 开通/续费会员 |
| `LUCKY_CARD` | 幸运卡 |
| `VIRTUAL_BENEFIT` | 通用虚拟权益商品 |
| `PROJECT_HEADLINE_CARD` | 头条卡 |
| `PROJECT_PIN_CARD` | 置顶卡 |
| `PROJECT_REFRESH_CARD` | 刷新卡 |
| `PROJECT_COLOR_CARD` | 变色卡 |
| `IDENTITY_VERIFICATION` | 实名认证收费订单 |

新项目存在其他付费订单时，先在项目规则和数据库枚举中增加稳定的 `ORDER_KIND`，再开放后台选择；禁止用商品名称字符串判断。

## 3. 服务端判定

1. 创建业务订单时写入不可变 `order_kind` 快照。
2. 查询收银台方式时只返回 `enabled=true`、provider 就绪、允许当前 `business_type` 且 `hidden_order_kinds` 不含当前 `order_kind` 的方式。
3. 发起在线支付、打开扫码弹窗、上传扫码截图和提交人工审核时都重新执行相同判定。
4. 被隐藏时统一返回 `PAYMENT_METHOD_DISABLED`，不泄露商户配置。
5. 后台配置变更立即影响尚未支付的订单；已支付/已审核完成订单保持历史方式快照。

## 4. 后台

- 支付方式行内显示名称、说明、开关、排序和“隐藏订单类型”多选项。
- 保存时使用枚举白名单、去重和数组类型校验；未知值拒绝，不静默丢弃。
- 配置变更记录操作者、修改前后值、时间和 request_id。
- `hidden_order_kinds=[]` 表示不按订单类型隐藏，升级后不得自动隐藏任何生产方式。

## 5. 验收

- 指定订单类型的收银台列表中不出现被隐藏方式；其他订单仍出现。
- 旧 APK 缓存了该方式时，直接发起支付仍被服务端拒绝。
- 人工扫码的打开、上传和提交路径同样拒绝绕过。
- 后台退出重登后配置保持；并发修改使用版本号或 ETag 防止覆盖。
