# 支付模块 V1.4.2 整合说明

## 事实源顺序

1. `MODULE_MANIFEST.yaml` 与 M-PAY 规则；
2. `PRIVATE_INTEGRATIONS.yaml#payment` 的私有服务端配置；
3. 富运、XApay、扫码审核和隐藏方式四份专项合同；
4. `PAYMENT_API_CONTRACTS.yaml`、`PAYMENT_DATABASE_SCHEMA.md` 与测试矩阵；
5. 新项目明确写入的业务类型、订单类型、商品权益和返佣规则。

## 新项目生成要求

- 只要新项目需要收款，启用同一个 payment 模块和 Android 原生统一收银台，不再让项目所有者重复描述 XApay 或扫码审核方案。
- 默认把富运、XApay和人工扫码作为可选 profile 写入项目配置；只启用需求选择的方式，关闭方式不出现在 App。
- XApay 只生成已确认的支付宝/微信在线方式；QQ 使用人工扫码。
- 扫码审核通过必须调用该项目统一商品/服务结算器，完整发放权益和返佣，不能只修改支付状态。
- 后台每种支付方式必须支持名称、说明、开关、排序、允许业务类型和隐藏订单类型。
- 项目域名、商品类型和 UI 以新项目事实源替换；商户私钥仍只在服务器 Secret/环境配置。

## V1.4.1 基线保护

本版从完整 V1.4.1 目录复制后增量更新支付模块、支付私有配置和支付入口索引。实名认证、R2、SMTP、提现、支付宝证书、账号、全局规则和 `12_原始参考资料` 不得因支付整合被删除、重写或缩减。
