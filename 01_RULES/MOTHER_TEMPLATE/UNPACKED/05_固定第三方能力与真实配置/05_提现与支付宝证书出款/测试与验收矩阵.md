# 提现与自动出款测试矩阵

## 自动化必测

- `0.30`、`1.00`、大额档位按两位小数往返，前端不显示为 0；
- 实名姓名由服务器锁定，客户端伪造姓名无效；
- 未实名、实名取消、未绑定、档位停用、余额不足和当日次数用尽；
- 同一幂等键重放、12 路以上并发提交，只冻结一次并只创建一单；
- 阈值以下、等于阈值、超过阈值和阈值为 0 的分流；
- 自动路径和人工审核一键出款路径；
- 假网关 `SUCCESS`、`DEALING`、终态失败、HTTP 失败、超时、畸形 JSON、错误签名；
- 未知结果禁止重试和退回，查单成功补结算，终态失败后允许退回；
- 私钥与应用证书不匹配、证书无效、缺文件、错误序列号时通道不就绪；
- 管理员权限、版本冲突、查看明文和所有高风险操作审计；
- 拒绝/退回是否恢复每日次数按配置生效；
- 余额账本满足冻结一次、成功或退回恰好一个终态事件。

## 非资金外部验证

- 服务器 DNS/TLS 可访问支付宝正式网关；
- 四份材料解析、匹配与有效期检查通过；
- 官方 SDK 计算的应用/根证书序列号与私有配置一致；
- 服务启动健康状态为 `CERTIFICATE + ready`；
- 业务自动开关未开启时不会发起真实转账。

## 真实小额验证

仅在项目所有者明确给出收款人、支付宝账号和单笔/总额上限后执行：

1. 先使用低于授权上限的独立订单号；
2. 记录请求号、支付宝订单号、签名响应、查单状态和账本，敏感字段脱敏；
3. 由收款人确认实际到账金额和付款方展示；
4. 不因一次成功推断长期可用，证书、权限、余额和风控持续监控。

未执行该节时，交付报告必须写“真实资金测试未执行”，不能写“自动打款真实到账通过”。
