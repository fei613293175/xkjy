# 提现与自动出款总规范

## 1. 功能目标

为存在平台余额的项目提供支付宝提现闭环：实名锁名绑定、固定档位、余额冻结、每日次数、后台审核、接口一键出款、小额自动出款、查单对账、失败退回、账本和审计。

本模块不等于支付宝账户“永久可用”。私钥与证书可复用到同一应用/主体的新项目，但实际出款仍受支付宝应用产品权限、证书有效期、账户余额、收款账号、单笔/日限额和风控影响。项目上线前必须重新执行服务端预检。

## 2. 前端页面组

- 提现首页：可用余额、规则、档位、服务费、预计到账、今日剩余次数；
- 支付宝绑定/修改：实名姓名由服务器返回且不可编辑，只填写支付宝账号；
- 提现确认：档位、费用、到账金额、收款账号掩码、规则确认；
- 提交结果：自动到账、审核中、出款中、失败/联系客服；
- 提现记录和详情：状态时间线、金额、费用、账号掩码、失败原因和流水号掩码。

客户端不得自行判断自动出款资格或最终到账，展示状态以服务器订单为准。

## 3. 提交流程

1. 查询配置、实名状态、绑定信息、余额和今日剩余次数。
2. 未实名时引导实名认证；已实名时绑定页显示锁定姓名。
3. 用户选择后端返回的有效档位并提交一次性安全票据与幂等键。
4. 服务端对用户加事务级互斥，重新读取档位、配置、实名、绑定和余额。
5. 单事务创建订单、保存收款快照、可用余额转冻结余额、写冻结账本。
6. 满足自动出款开关和阈值则立即发起接口；否则返回 `PENDING_REVIEW`。
7. 管理员审核通过后点击一键出款；业务服务不把密钥交给后台浏览器。
8. 支付宝确认成功后扣减冻结金额并写成功账本；未知结果进入待对账。
9. 终态失败经查单确认后可重试或退回。

## 4. 金额与次数

- 档位金额必须大于 0，按两位小数存储和传输；
- 手续费不得大于等于档位金额，净额至少 `0.01` 元；
- 自动阈值按申请毛额判断，包含边界值；
- 每日次数使用项目业务时区的半开区间 `[dayStart, nextDayStart)`；
- 同一幂等请求重放返回原订单，不重复扣余额或次数；
- 拒绝/失败退回是否恢复次数作为明确配置，默认恢复；
- 历史订单永远保留提交时的档位、费率、费用和配置快照。

## 5. 自动与人工场景

| 场景 | 用户响应 | 后台状态 | 出款执行者 |
|---|---|---|---|
| 自动开关开启且金额不高于阈值 | 成功时“提现已到账”；处理中时显示处理中 | 自动记录结果 | 后端立即调用支付宝 |
| 不满足阈值或自动关闭 | “提现申请成功，等待平台审核” | `PENDING_REVIEW` | 管理员审核后点击一键出款，后端调用支付宝 |
| 支付宝结果未知 | “出款处理中，请勿重复提交” | 待对账 | 后端定时/人工查单 |
| 支付宝终态失败 | 显示失败原因或联系客服 | 可重试/退回 | 有权限管理员 |

“人工审核”不等于人工填写已付款：一键出款仍通过证书接口，只有项目明确保留线下出款渠道时才能另设独立状态和凭证审计。

## 6. 安全与隐私

- 姓名和账号采用 AES-256-GCM 等带认证加密，项目独立密钥只在服务器；
- 列表、日志和普通 API 只返回掩码；查看明文需要独立权限并记录审计；
- 订单持有加密快照，不依赖可变的绑定表；
- 私钥不得存数据库或后台表单，证书文件以只读 Secret 挂载；
- 配置保存前验证阈值、档位、次数、理由和备注，并返回字段级中文错误；
- 提现相关接口必须有认证、CSRF/票据、频控、幂等和 request_id。

## 7. 运营配置

- 模块总开关；
- 提现档位、排序、启停、累计次数（项目需要时）；
- 会员/非会员或统一手续费规则；
- 每日最多提现次数；
- 拒绝或资金退回是否恢复次数；
- 提现后最低剩余余额；
- 自动出款开关和最高毛额；
- 支付宝 `order_title`/出款理由和 `remark`/转账备注；
- 前端提现规则和各状态中文文案；
- 查单间隔、最大次数和告警阈值；
- 证书渠道只读健康状态，不在后台返回私钥。
