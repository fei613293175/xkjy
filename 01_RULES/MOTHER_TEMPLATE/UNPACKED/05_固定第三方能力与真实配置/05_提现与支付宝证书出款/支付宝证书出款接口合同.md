# 支付宝证书出款接口合同

## 固定通道

```text
Gateway: https://openapi.alipay.com/gateway.do
Sign type: RSA2
Mode: 应用证书 + 支付宝证书 + 支付宝根证书
Transfer method: alipay.fund.trans.uni.transfer
Query method: alipay.fund.trans.common.query
Product code: TRANS_ACCOUNT_NO_PWD
Biz scene: DIRECT_TRANSFER
Payee identity type: ALIPAY_LOGON_ID
```

## 转账业务参数

| 字段 | 规则 |
|---|---|
| `out_biz_no` | 服务端全局唯一，最长 64，失败重试策略可追踪 |
| `trans_amount` | 净到账金额，两位小数字符串 |
| `order_title` | 后台配置的提现理由，非空且受长度限制 |
| `remark` | 后台配置的转账备注，非空且受长度限制 |
| `payee_info.identity` | 提交时加密快照解密所得支付宝账号 |
| `payee_info.name` | 提交时实名姓名快照，不能取客户端输入 |
| `business_params` | 可请求 `payer_show_name_use_alias=true` |

## 公共参数与签名

公共参数至少包含 `app_id`、`method`、`format=JSON`、`charset=utf-8`、`sign_type=RSA2`、`timestamp`、`version=1.0`、`biz_content`、`app_cert_sn`、`alipay_root_cert_sn`。按键名字典序拼接非空值，使用应用私钥执行 SHA256withRSA 签名。

证书序列号必须使用支付宝官方 SDK 的算法生成。不要用普通 X.509 serial number 代替 `app_cert_sn`，也不要自行猜测根证书包多证书序列号拼接规则。

## 响应验签

从原始响应文本提取与 method 对应的 `*_response` 原始 JSON 值，使用支付宝证书公钥验证 `sign`。不能把 JSON parse 后重新序列化再验签，因为键顺序/转义变化会破坏签名。验签不通过不得读取业务状态或结算。

## 状态映射

- `code=10000` 且 `status=SUCCESS`：确认成功；
- `DEALING` / `WAIT_PAY`：处理中，进入查单；
- `FAIL` / `CLOSED` / `REFUND`：候选终态失败，仍建议查单确认；
- HTTP/网络/超时/解析/验签异常：结果未知，禁止重试或退回，先查单；
- 查单成功：补结算；查单终态失败或明确不存在：允许新尝试或退回。

## 启动预检

服务启用自动出款前必须验证：

1. 四个文件存在且运行用户可读，私钥文件不是宽权限；
2. 私钥可解析且与应用证书公钥匹配；
3. 应用证书和支付宝证书在有效期内；
4. 根证书包可解析；
5. App ID、应用证书序列号和根证书序列号均存在；
6. 网关是允许列表内 HTTPS 地址；
7. 本地签名/验签自测通过。

预检失败时渠道状态为 `NOT_READY`，自动出款开关不可保存为开启；错误仅返回稳定错误码，不输出密钥或证书正文。
